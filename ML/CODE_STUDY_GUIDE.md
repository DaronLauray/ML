# NBA Winner Predictor: Code Study Guide

This document explains how the project works so you can maintain, improve, or eventually rebuild it yourself.

## 1. What the Project Does

The project has four main stages:

1. Read historical NBA CSV files.
2. Convert raw team and player records into recent-form features.
3. Train a machine-learning classifier that predicts whether the home team wins.
4. Provide predictions through a browser UI or Python function.

The main prediction target is:

```text
home_win = 1  -> home team won
home_win = 0  -> away team won
```

The model does not predict a score. It predicts a class and then converts the model's class probabilities into home and away win probabilities.

## 2. Important Files

### `nba_winner_predictor.py`

This is the core machine-learning program. It owns data loading, feature engineering, training, model saving, model loading, and prediction.

### `nba_winner_model.joblib`

This is the trained model artifact. It contains a dictionary with:

- `model`: the trained `RandomForestClassifier`
- `features`: the feature column names used during training
- `team_features`: historical team rows with rolling statistics

Do not edit this file manually. It is generated by `joblib.dump()` and should be recreated by training code.

### `app.py`

This is the Flask web server. It receives browser requests, calls the prediction code, and returns HTML or JSON.

### `templates/index.html`

This is the browser UI. It contains the page layout, CSS styling, team dropdowns, browser-side JavaScript, and the request sent to Flask.

### `test_make_prediction_debug.py`

This is a focused test script. It loads the model, checks the stored data types, and makes one sample prediction.

### `test_model.py`

This checks whether the joblib file can be opened and whether it contains the expected model payload.

### `requirements.txt`

This lists the Python packages needed by the project.

## 3. How the Web Request Works

When you open the site:

```text
Browser -> GET / -> app.py -> load_model() -> index.html
```

When you click **Predict Winner**:

```text
Browser JavaScript
    -> POST /api/predict
    -> app.py: predict()
    -> nba_winner_predictor.py: make_prediction()
    -> RandomForest model
    -> JSON response
    -> browser displays result
```

The browser sends data similar to:

```json
{
  "home_team": "Celtics",
  "away_team": "Lakers",
  "date": "2026-09-15"
}
```

The server returns data similar to:

```json
{
  "prediction": "Celtics",
  "home_probability": 0.61,
  "away_probability": 0.39,
  "explanation": ["diff_avg5_plusMinusPoints: 0.0699"]
}
```

## 4. Understanding `app.py`

### Flask application setup

```python
from flask import Flask, render_template, request, jsonify

app = Flask(__name__)
```

`Flask(__name__)` creates the web application. Flask maps URLs to Python functions using decorators.

### Home page route

```python
@app.route('/')
def home():
```

This route runs when the browser requests `/`.

It loads the model and obtains the available team names:

```python
model, features, team_features = load_model()
teams = sorted(team_features['teamName'].unique().tolist())
```

Then it sends those teams into the HTML template:

```python
return render_template('index.html', teams=teams)
```

Inside the HTML file, Flask makes the Python list available to JavaScript using `teams|tojson`.

### Prediction API route

```python
@app.route('/api/predict', methods=['POST'])
def predict():
```

This route accepts JSON from the browser.

```python
data = request.get_json(silent=True) or {}
home_team = data.get('home_team', '').strip()
away_team = data.get('away_team', '').strip()
```

The route validates that both team fields exist, calls `make_prediction()`, and returns the result as JSON.

A `400` response means the request was invalid. A `500` response generally means the server itself failed while handling the request.

### Team API route

```python
@app.route('/api/teams', methods=['GET'])
def get_teams():
```

This route is useful for testing. It returns the team names known by the saved model.

### Starting the server

```python
if __name__ == '__main__':
    app.run(debug=True, port=5000)
```

The `if` statement means the server starts only when `app.py` is run directly.

`debug=True` is convenient during development because Flask reloads after code changes. Do not use debug mode for a public production server.

## 5. Understanding the Data Loaders

All data files are under:

```text
Data/
```

The code builds paths relative to the Python file:

```python
DATA_DIR = os.path.join(os.path.dirname(__file__), 'Data')
```

This is safer than assuming the terminal's current directory is always correct.

### `load_games()`

This loads `Games.csv`. It creates the target column:

```python
games['home_win'] = (games['winner'] == games['hometeamId']).astype(int)
```

The comparison checks whether the recorded winner ID equals the home team ID.

It also converts dates using:

```python
pd.to_datetime(..., utc=True, errors='coerce')
```

Important meanings:

- `utc=True`: make timestamps comparable across sources
- `errors='coerce'`: invalid dates become `NaT` instead of crashing
- `dropna(...)`: remove rows without usable dates

The rows are sorted chronologically so the training test split respects time.

### `load_team_stats()`

This loads regular team box-score statistics such as:

- points
- assists
- turnovers
- rebounds
- shooting percentages
- fast-break points
- points in the paint
- plus/minus

`usecols` intentionally reads only needed columns. This reduces memory usage.

The loader converts numerical columns with:

```python
pd.to_numeric(column, errors='coerce')
```

That protects the pipeline when a CSV contains text or malformed numeric values.

### `load_team_advanced()`

This loads advanced statistics and keeps:

- `netRating`
- `offRating`
- `defRating`

These are later merged into the team statistics by `gameId` and `teamId`.

### Player loaders

`load_player_usage()` loads player usage percentage.

`load_player_stats()` loads player points. It uses the Python CSV engine and skips malformed rows:

```python
engine='python'
on_bad_lines='skip'
```

This was added because the player CSV contains problematic rows and can be too large for the default parser.

## 6. Player Feature Engineering

The function `build_player_features()` turns many player rows into smaller team-game indicators.

First, usage is grouped by game and player:

```python
usage.groupby(['gameId', 'playerteamName'])['usgPct'].max()
```

This creates `max_usgPct`, the maximum recorded usage for that player in that game.

Points are sorted from highest to lowest and the first three records are selected:

```python
stats.sort_values(...)
stats.groupby(['gameId', 'playerteamName']).head(3)
```

The result is aggregated into `top3_points`.

The two player tables are merged, and missing values are replaced with zero. This means missing player data does not crash training.

## 7. Team-Game Feature Engineering

The function `build_team_game_features()` combines regular team stats, advanced team stats, and player features.

### Merging team and advanced data

```python
pd.merge(
    team_stats,
    advanced[['gameId', 'teamId', 'netRating', 'offRating', 'defRating']],
    on=['gameId', 'teamId'],
    how='left'
)
```

A left merge keeps the team-stat row even if advanced statistics are missing.

### Merging player data

Player features are connected using:

```text
team_stats.gameId     = player_features.gameId
team_stats.teamName   = player_features.playerteamName
```

### Preventing future data leakage

The most important idea in this project is that a game must be predicted using information available before that game.

The code sorts each team's games by date, then shifts the data by one game:

```python
group[col].shift(1)
```

The shift prevents the current game's final result from appearing in its own prediction features.

Then it calculates a rolling five-game mean:

```python
group[col].shift(1).rolling(5, min_periods=1).mean()
```

For example, `avg5_teamScore` means the team's average score from recent previous games, excluding the current game.

### Generated rolling columns

The current feature list contains 17 values:

```text
avg5_teamScore
avg5_assists
avg5_turnovers
avg5_reboundsTotal
avg5_fieldGoalsPercentage
avg5_threePointersPercentage
avg5_freeThrowsPercentage
avg5_pointsFastBreak
avg5_pointsFromTurnovers
avg5_pointsInThePaint
avg5_pointsSecondChance
avg5_plusMinusPoints
avg5_netRating
avg5_offRating
avg5_defRating
avg5_top3_points
avg5_max_usgPct
```

## 8. Building Matchups

`build_matchup_dataset()` creates one row per game containing home and away features.

It separates team rows using the `home` flag:

```python
home_features = team_features[team_features['home'] == 1]
away_features = team_features[team_features['home'] == 0]
```

It then merges both sides onto the game ID.

For every statistic, it creates a difference:

```python
home_stat - away_stat
```

For example:

```text
diff_avg5_teamScore = home team's recent scoring average
                       - away team's recent scoring average
```

The classifier trains on these 17 differential columns rather than raw team names. This lets the model compare the two teams' recent form directly.

## 9. Training the Model

The `train_model()` function performs these steps:

1. Build the matchup dataset.
2. Sort games by date.
3. Split the first 80% into training data and the last 20% into testing data.
4. Train a random forest.
5. Calculate accuracy and a classification report.
6. Save the model payload to `nba_winner_model.joblib`.

The model is created here:

```python
RandomForestClassifier(
    n_estimators=200,
    random_state=42,
    n_jobs=-1,
    class_weight='balanced'
)
```

Meaning:

- `n_estimators=200`: build 200 decision trees
- `random_state=42`: make the result reproducible
- `n_jobs=-1`: use available CPU cores
- `class_weight='balanced'`: compensate for uneven win classes

The chronological split is important. A random split can accidentally train on future games and test on older games, which produces misleading results.

## 10. Loading and Predicting

### `load_model()`

This opens the joblib file and normalizes loaded values.

The model file is not edited. Instead, the loaded copy of `team_features` is cleaned:

- dates are converted to UTC datetimes
- invalid dates are removed
- missing team names are removed
- team names are converted to trimmed strings

This prevents errors such as:

```text
'<' not supported between instances of 'str' and 'float'
```

That error happens when Python tries to sort or compare strings and floating-point `NaN` values together.

### `make_prediction()`

The prediction function:

1. Loads the saved model.
2. Validates the team names.
3. Chooses the requested date, or the latest available date.
4. Finds each team's latest historical feature row before that date.
5. Calculates home-minus-away feature differences.
6. Replaces missing or infinite values with zero.
7. Calls `model.predict_proba()`.
8. Selects the team with the larger probability.
9. Returns the prediction and feature importance explanation.

The output probability values are model probabilities, not guarantees. They should not be treated as certainty.

## 16. Important Limitations

The current model is an educational prediction system, not a guaranteed betting system.

Known limitations include:

- Test accuracy is approximately 58%.
- Historical player availability and injuries are not included.
- The model does not know future lineups, rest, travel, weather, or betting-market movement.
- Some old team names exist in the historical data.
- Missing feature values are currently filled with zero during prediction.
- A high probability is not a guarantee of winning.

For serious evaluation, track predictions against future games and calculate calibration, profit/loss after sportsbook fees and vig, and performance against a baseline such as always choosing the home team.
